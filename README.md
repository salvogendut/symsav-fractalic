# symsav-fractalic

A fractal screensaver for [SymbOS](https://www.symbos.org/) on the Amstrad CPC.

> **Requires Mode 1** — this screensaver only works in 320×200 Mode 1 (4 colours). Running it in any other screen mode will produce incorrect output.

---

## Building

```bash
./build.sh
```

Requires the SCC compiler (set `SCC=` env var if not at `../scc/bin/cc`) and Python 3.

Build steps:

1. SCC compiles `fractalic.c` → `fractalic.sav`
2. `add_preview.py` patches the preview thumbnail into the binary at file offset 256

Output: `fractalic.sav`

---

## Installing

1. Copy `fractalic.sav` into your `C:\SYMBOS\` directory.
2. Open **Display Properties** and go to the **Screen Saver** tab.
3. Click **Browse** and select `fractalic.sav`.
4. Click **Setup** to configure the effect:
   - **Fractal**: Sierp. / Koch / Dragon / Fern / **Random** — which fractal to draw. Choosing *Random* cycles through all four types in a different random order each time.
   - **Depth**: Low / Med / High — iteration count or point density (controls detail level and rendering time)
   - **Speed**: Slow / Normal / Fast — steps drawn per animation tick

After each fractal is fully rendered the image is held for 5 seconds, the screen clears, and a new fractal begins.

## Fractal types

### Sierpinski triangle
The classic gasket drawn via the *chaos game*: a point bounces randomly between the three triangle vertices, always moving halfway to the chosen vertex. After thousands of iterations the Sierpinski triangle emerges as a by-product of the random walk. Rendered in three inks — one per vertex region.

### Koch snowflake
Starts with an equilateral triangle. Each iteration replaces every line segment with four shorter ones — the middle third is replaced by two sides of an equilateral triangle — producing the characteristic spiky snowflake outline. Depth 1–3 yields 12–192 segments, drawn one by one from base triangle outward.

### Dragon curve
A self-similar curve generated by iteratively folding a strip of paper in half and unfolding it flat. The turn sequence is stored as packed bits (1 bit per turn) and replayed as a series of unit steps on a grid. At 9–11 folds the curve produces 512–2047 segments that tile the plane without overlapping.

### Barnsley fern
An Iterated Function System (IFS) using four affine transforms that together converge on the outline of a fern frond. Each point is mapped by a randomly chosen transform (weighted by probability) and the orbit is plotted. The three inks are assigned by height, giving the frond a gradient from stem to tip.

## Colours

All fractals use the SymbOS default Mode-1 palette with ink 1 (black, `0xF0` per byte) as the background:

| Ink | Appearance | Usage |
|-----|-----------|-------|
| 0 | White | Highlights / high regions |
| 2 | Dim | Mid tones |
| 3 | Bright | Foreground / low regions |

## Screensaver protocol

Standard SymbOS screensaver messages:

| Message | Action |
|---------|--------|
| `MSC_SAV_INIT` (1) | Load saved config from manager |
| `MSC_SAV_START` (2) | Start fullscreen animation |
| `MSC_SAV_CONFIG` (3) | Open config dialog |
| `MSR_SAV_CONFIG` (4) | Send updated config back |

Config is 7 bytes: magic `"FRAC"` + type byte (0=Random, 1=Sierpinski, 2=Koch, 3=Dragon, 4=Fern) + depth byte + speed byte.

## Animation

Fullscreen rendering follows the same approach as [symsav-xroach](https://github.com/salvogendut/symsav-xroach) and [symsav-xmatrix](https://github.com/salvogendut/symsav-xmatrix):

1. Open a fullscreen `WIN_NOTTASKBAR | WIN_NOTMOVEABLE` window
2. `DSK_SRV_DSKSTP` to freeze the desktop
3. Clear all 8 CPC character planes via `Bank_Copy` to VRAM (bank 0, all bytes = `0xF0` = ink 1 = black)
4. Per tick: advance the current fractal algorithm by N steps (N scales with the Speed setting)
5. When done: hold for ~300 ticks (~5 s), then clear and start the next fractal
6. Exit on any key or mouse movement: resume desktop, close window, `Screen_Redraw()`

VRAM address formula for pixel (x, y):

```
addr = 0xC000 + (y/8)*80 + (y%8)*0x800 + x/4
```

Mode-1 pixel encoding within each byte (4 pixels per byte):

```
bit7=p0_lo  bit6=p1_lo  bit5=p2_lo  bit4=p3_lo
bit3=p0_hi  bit2=p1_hi  bit1=p2_hi  bit0=p3_hi
```

Individual pixel writes use a `Bank_Copy` read-modify-write (1 byte from VRAM → mask in the target pixel bits → write back). Filled rectangles (used for the screen clear) use a pre-filled scanline buffer written with a single `Bank_Copy` per scanline.

## Implementation notes

- **No recursion** — Koch snowflake expansion and Dragon curve generation use iterative loops with explicit arrays in the `_data` segment, sidestepping SCC stack-depth limits.
- **Fixed-point arithmetic** — the Barnsley fern IFS uses integer coefficients scaled by 256, keeping all multiplications within 16-bit signed range.
- **Contiguous `_transfer` layout** — all `Ctrl` structs for the config dialog are declared in source order so that `cfgcg.first = &ccc0` correctly addresses a contiguous array, as required by the SymbOS window manager.
